Un seul défaut bloquait réellement la cible — la commande python dans le serveur de prévisualisation. Il est corrigé, et la suite de tests passe désormais des deux côtés. Le vrai chantier n'est pas le code : c'est ComfyUI / DirectML, qui doit être reconstruit en ROCm, et deux données irremplaçables que git ne réplique pas.

Réserves de mesure qui s'appliquent à tout ce document

Les tests ont tourné dans WSL Ubuntu-26.04, dont la userland est exactement celle de la cible. Trois écarts subsistent et bornent ce qui est prouvé :

  • Noyau WSL — 6.6.87.2-microsoft-standard-WSL2, pas un noyau Ubuntu. Rien de ce qui touche systemd, udev, l'audio, le GPU ou le réseau bas niveau n'est prouvé ici. Les versions de paquets, elles, sont valides.
  • Utilisateur root (uid 0). Aucun test ne dit rien des permissions de fichiers ni de ce qui exigera une élévation sur ta machine.
  • Locale C.UTF-8, quand la cible sera française. La suite a été rejouée avec LANG=fr_FR.UTF-8 (verte), mais aucun test n'a exercé un tri ou un format de date sous locale française réelle.

S'y ajoute que Kubuntu n'est pas Ubuntu quant au bureau : les paquets sont identiques, mais l'environnement est KDE Plasma 6. Les procédures ci-dessous sont écrites pour KDE (autostart XDG, systemd --user), pas pour GNOME.

Chaque test WSL a été précédé d'un contrôle de provenance des binaires (command -v) : aucun chemin en /mnt/, donc aucune mesure Windows déguisée en mesure Linux.

2. Fiches — ce qui ne migre pas

F1 — Pipeline d'assets IA : ComfyUI sous DirectML bloquant

Quoi
Installation ComfyUI complète en C:\ComfyUI (avec .venv), figée sur le tag v0.7.0, backend --directml, plus ~31 Go de modèles dans C:\ComfyUI\models\ (checkpoints 13 Go, clip_vision 2,4 Go, ipadapter 809 Mo, loras 28 Mo).
Où
Hors dépôt, au niveau machine. Révélé par Test-Path C:\ComfyUI et la lecture de Snake'on/ia-assets/PIPELINE-ASSETS-IA.md.
Rôle
Génère des morceaux de skins (SDXL + IPAdapter) pilotés par les deux scripts generate_piece*.ps1, qui postent un workflow JSON sur http://127.0.0.1:8188 et sondent /history. Outil d'exploration : aucun asset généré n'est intégré au jeu, qui reste 100 % procédural.
Déclenchement
Manuel, à la demande, compte utilisateur, sans privilèges particuliers.
Pourquoi ça ne migre pas
Ce n'est pas une question de fichiers mais de backend de calcul. DirectML est une couche Windows ; sous Linux la RX 7900 GRE passe par ROCm. Les roues PyTorch sont différentes, et la contrainte qui force ComfyUI à rester en v0.7.0 (incompatibilité avec torch-directml) disparaît avec DirectML. Copier le dossier ne produirait qu'une installation morte.
Équivalent recommandé
ComfyUI + PyTorch ROCm 7.2, qui supporte officiellement la RX 7900 GRE (gfx1100) — c'est la voie que ta propre documentation identifie, et elle débloque en prime l'entraînement LoRA, impraticable sous DirectML.
Alternative sérieuse : le paquet Vulkan / llama-style (ComfyUI sur backend Vulkan), qui évite l'installation ROCm et ses ~20 Go de dépendances. Ce qui les départage : ROCm offre les performances et l'écosystème PyTorch complet (donc l'entraînement) au prix d'une installation lourde et d'un couplage fort à la version du noyau ; Vulkan s'installe en quelques minutes et survit aux mises à jour, mais reste plus lent et ne permet pas l'entraînement. Pour ton usage — entraînement LoRA visé — ROCm est le bon choix, Vulkan étant le repli si l'installation ROCm résiste.
Vérification
python3 -c "import torch; print(torch.__version__, torch.cuda.is_available(), torch.cuda.get_device_name(0))"
# attendu : une version +rocm, True, et "Radeon RX 7900 GRE"
curl -s http://127.0.0.1:8188/system_stats | head -c 400
Ordre
Après les pilotes GPU. Ne dépend de rien d'autre du projet.

F2 — pwsh absent des dépôts Ubuntu à corriger

Quoi
Les deux scripts generate_piece.ps1 et generate_piece_flux.ps1 exigent PowerShell 7.
Où
Snake'on/ia-assets/, versionnés depuis 76f24eb.
Rôle
Construire le workflow JSON ComfyUI, le poster, sonder le résultat.
Pourquoi ça ne migre pas
Pas à cause de leur code — ils n'utilisent que des cmdlets multi-plateformes (Invoke-RestMethod, ConvertTo-Json, Stopwatch), aucun COM ni WMI. Le problème est l'interpréteur : apt-cache policy powershell rend une sortie vide sur Ubuntu 26.04, et aucun dépôt Microsoft n'est configuré par défaut.
Équivalent recommandé
Installer pwsh depuis le dépôt Microsoft et garder les scripts tels quels (~15 min).
Alternative sérieuse : les réécrire en Python (~60 lignes chacun, requests + boucle de sonde, ~1 h).
Ce qui les départage : la réécriture supprime une dépendance hors dépôts et une source de divergence entre deux versions du même script, mais coûte du temps et introduit un risque de régression sur un outil qui marche. Je recommande pwsh — et surtout de ne trancher qu'après avoir remonté ComfyUI (F1) : si l'API change au passage à ROCm, le script changera de toute façon, et réécrire maintenant serait outiller le rattrapage avant d'avoir traité la cause.
Procédure
sudo apt-get -o DPkg::Lock::Timeout=120 install -y wget apt-transport-https
source /etc/os-release
wget -q "https://packages.microsoft.com/config/ubuntu/$VERSION_ID/packages-microsoft-prod.deb"
sudo dpkg -i packages-microsoft-prod.deb && rm packages-microsoft-prod.deb
sudo apt-get update && sudo apt-get install -y powershell
Si le paquet pour 26.04 n'existe pas encore chez Microsoft au moment de la bascule, retomber sur la version 24.04 du dépôt, ou choisir la réécriture Python.
Vérification
pwsh -NoProfile -Command '$PSVersionTable.PSVersion'
Ordre
Après F1 — inutile sans ComfyUI.

F3 — Identifiants GitHub protégés par DPAPI à corriger

Quoi
Trois entrées du Gestionnaire d'identification Windows : git:https://github.com (compte ProlexAi), gh:github.com:ProlexAi, GitHub for Visual Studio.
Où
Credential Manager. Révélé par cmdkey /list — aucune valeur n'a été lue ni recopiée.
Rôle
Authentifier les git push vers mini-jeux. Le remote est en https://, pas en SSH : la clé id_ed25519 ne sert pas à ça.
Pourquoi ça ne migre pas
DPAPI chiffre ces secrets avec des clés dérivées du compte Windows et du matériel. Ils ne sont pas exportables en clair. C'est une recréation, jamais une copie — et c'est une bonne chose.
Équivalent recommandé
gh auth login (GitHub CLI), qui configure aussi le credential helper git.
Alternative : git-credential-libsecret adossé au trousseau KDE (KWallet via l'API Secret Service). Ce qui les départage : gh couvre en une commande l'authentification git et l'API GitHub, et gère le renouvellement du jeton ; libsecret est plus générique mais demande de créer et coller un jeton à la main. Sur Kubuntu, gh est le bon choix, KWallet servant de coffre en dessous.
Procédure
sudo apt-get install -y gh git
gh auth login          # HTTPS, authentification par navigateur
gh auth setup-git
Vérification
gh auth status
git -C ~/mini-jeux ls-remote origin >/dev/null && echo "push authentifie OK"
Ordre
En premier — sans lui, impossible de récupérer le dépôt.

7. Réserves et angles morts

Ce qui n'a pas pu être vérifié, et la commande qui le trancherait.

  • Kubuntu n'a jamais été testé. Toutes les mesures viennent d'Ubuntu 26.04 sous WSL, qui partage les dépôts mais pas le bureau ni le noyau. Ce qui reste non prouvé : le comportement sous KDE Plasma 6, l'accès GPU réel, les permissions hors root. Tranche : rejouer docs/migration-linux/restauration-linux.sh sur la machine cible.
  • La clé SSH. Tranché le 2026-09-05 : même paire. puttygen n'étant pas installé, la partie publique du .ppk a été lue directement — elle est en clair dans le fichier, la lecture s'arrête net avant les Private-Lines. Les deux empreintes SHA-256 sont identiques. La clé est donc déjà sauvegardée au format PuTTY ; rien à régénérer, rien à faire sur le VPS. Témoin joué avant le verdict : une paire jetable rend bien une empreinte différente.
  • Le support de sauvegarde est contesté entre deux sources. C:\Prolex_Core\docs\migration-linux\roadmap-kubuntu-2604.md (2026-09-04) écrit que D: est une clé de flashage BIOS « qu'il ne faut pas toucher » et recommande d'acheter un disque externe. Mais l'état réel du support le contredit : il porte déjà sauvegarde-migration-20260904-1924, complement-20260905 et secrets-et-hors-git-20260905, ce dernier écrit le jour même.
