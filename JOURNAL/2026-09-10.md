## Ce que je retiens, et qui vaut plus que la liste des livrables

**Ce sont les contre-passes qui ont trouvé les vrais défauts.** Mes propres vérifications avaient
laissé passer l'arrivant tardif : je n'avais testé que des joueurs présents avant le lancement.
Un agent qui n'avait pas écrit le code l'a vu.

**Trois pièges de banc ont coûté une passe de test chacun** : un service worker qui sert une
version fantôme, une qualité graphique qui se dégrade toute seule sous 30 fps, un onglet non
visible qui suspend `requestAnimationFrame`. Tous les trois sont consignés avec la commande qui
les détecte — c'est ce qui évitera de les repayer.

**Trois fausses alertes, toutes de mon fait**, sur la passe de non-régression : rayon figé,
reprise après pause, DASH inerte. Trois fois l'instrument contournait l'API du jeu. Le code était
juste.

**Une faute de méthode assumée** : le critère d'arrêt de l'encodeur QR a été posé *en cours de
route*, pas avant de commencer. Posé après coup, il ne protège qu'à moitié — et j'ai gaspillé une
de mes deux tentatives sur un instrument de diagnostic invalide.

**Un message de commit abîmé** (`40b959e`) : des backticks dans une chaîne bash ont été exécutés
par le shell. Réparé par une note git plutôt que par un `push --force` sur une branche publique.
Parade adoptée ensuite : `git commit -F`, jamais `-m` avec des backticks.
