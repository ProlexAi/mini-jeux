## Point 1 — Fusion de `migration-linux` dans `main` ✅

**Ce qui était cassé sur `main`, mesuré avant l'opération :**

| Défaut | Preuve |
|---|---|
| `launch.json` appelait `python`, absent de Kubuntu | `command -v python` → rien ; `python3` → 3.14.4 |
| contrôle de traductions en échec, EXIT 1 | `secKillEffects`/`secShopEffects` citées en `data-i18n` sans exister dans aucun dictionnaire → deux titres de boutique non traduits dans les 5 langues non-françaises |
| le même contrôle criait 9 faux positifs | clés vues mortes alors qu'appelées par `t('rank_'+id)` ou via `descKey` |
| `build_style_sheet.py` écrivait dans `C:\ComfyUI\input` en dur | échec **silencieux** sous Linux : `os.path.isdir` sautait la copie sans rien dire |
| aucun `.gitattributes` | la cohérence LF ne tenait qu'au `core.autocrlf` de la machine Windows, disparue |

**Conduite.** Backup poussé avant toute opération
(`backup-main-avant-merge-linux-20260907-1853`), fusion jouée **à blanc** d'abord —
`git merge-tree --write-tree`, qui ne touche ni branche ni arbre de travail — pour connaître
le conflit avant de le rencontrer. Verdict : un seul, `.gitignore`, en ajout/ajout.

Travail conduit dans un worktree isolé, le worktree principal restant sur `main`.

**Le piège des 772 lignes.** Le diff direct `main` → `migration-linux` affichait −772 lignes
sur `index.html`, ce qui ressemblait à une perte massive. C'était un artefact de comparaison
entre deux états divergés, pas un contenu supprimé. Preuve arithmétique après fusion :
**8289 + 6 = 8295 lignes**, aucune ligne perdue.

**Résolution du conflit.** Les deux `.gitignore` n'avaient aucune ligne contradictoire —
concaténation. Une troisième entrée a été ajoutée au passage : `.claude/worktrees/` n'était
pas ignoré, un arbre de travail complet pouvait donc entrer dans le dépôt. Le
`?? .claude/worktrees/` qu'affichait `git status` avant la fusion l'a confirmé sur pièce.

**Contrôles après fusion :**

```bash
node "Snake'on/verifie-traductions.js"           # OK — 6 langues, 130 clés, EXIT=0
python3 "Snake'on/ia-assets/verifie-chemins.py"  # VERDICT correct, EXIT=0
```

Le premier est **son propre témoin** : il rendait EXIT=1 sur `main` vingt minutes plus tôt.
Il a mordu, puis relâché quand le défaut a disparu.

## Point 3 — `Snake'on/README.md` remis face au code ✅

Le README décrivait l'état d'avant le passage à l'échelle agar.io du 22/08 au soir. Six
chiffres faux, dont une contradiction interne (45 bots à la ligne 4, 150 à la ligne 24).

| | écrit | réel |
|---|---|---|
| bots (accroche) | 45 | 187 (`BOT_COUNT_SOLO`) |
| bots (corps) | 150 | 187 |
| taille du monde | 16 écrans | 58 (`WORLD_SCREENS`) |
| plafond d'un axe | 6000 px | 20000 (`WORLD_MAX`) |
| mondes calculés | 4400×2800 / 1987×2650 | 8377×5331 / 3784×5045 |
| nourriture | 560 / 239 | 2030 / 868 |
| `BOT_MAX_LENGTH` | 300 | 800 |

**Les dimensions ne sont pas estimées.** Elles sortent d'un script qui lit les constantes dans
`index.html` et rejoue `computeWorld()`. Ce script **porte son témoin dans l'instrument** :
joué à `WORLD_SCREENS=16` sur 1100×700, il doit retrouver le 4400×2800 historique du README,
sinon il refuse de publier un chiffre. Le témoin a mordu, les valeurs à 58 écrans en découlent.

**Ce qui n'a pas été repris à l'aveugle** : la colonne « adversaires visibles ». Son ancienne
méthode n'est pas reconstituable (45/16 rend 2,81, pas le 1,9 écrit). Elle est désormais
calculée par une méthode **nommée dans le document** — `BOT_COUNT_SOLO ÷ WORLD_SCREENS` —
donc vérifiable. C'est aussi pourquoi les deux lignes sont identiques : le monde est
dimensionné à densité constante, et le code le dit.

## Point 5 — `analyse-concurrence.md` annoté ✅

Le §1 se terminait par « il reste ouvert » à propos du rapport de force illisible entre deux
serpents au plafond de rayon. Sa propre règle d'écriture l'exigeait : *« une entrée n'est
jamais supprimée ; si elle devient fausse, on l'annote sans l'effacer »*.

**La nuance compte, et une lecture rapide la rate.** Mesure faite :

```bash
grep -nE "^ +(MAX_RADIUS|RADIUS_EXPONENT):" "Snake'on/index.html"
```

Le rayon est **toujours** plafonné en dur (`MAX_RADIUS: 130`, `Math.min` ligne 4764). Deux
serpents au plafond ont donc toujours la même épaisseur : le constat physique du §1 reste
exact. Ce qui a changé le 22/08 (`c25a2c6`), c'est l'ajout d'un **second canal visuel** qui
porte l'information que l'épaisseur ne porte plus — `threatLevel()`, rendu sur le serpent et
repris sur la minimap.

L'écart est donc **compensé, pas supprimé** : retirer le liseré rouvrirait le point tel quel.

## Publication

`main` poussée, 16 commits. Déploiement vérifié **en ligne**, pas seulement en local.

**Un contrôle raté au passage, à ne pas refaire.** Le premier marqueur choisi pour attendre
GitHub Pages était `secKillEffects` — qui existait **déjà** dans le HTML déployé, en
`data-i18n`. Le contrôle rendait vrai avant comme après : il ne discriminait rien, et a
« réussi » en 0 seconde. Marqueur repris sous sa forme dictionnaire, `secKillEffects:`,
qui vaut 0 avant le push et 6 après. Vérification close par empreinte :

```
md5 local == md5 déployé  →  3a9e0a32c9e8482a09a450c97d56590d
```

**La leçon** : un marqueur de déploiement doit être une chaîne que la version *précédente*
ne contient pas. Sinon on mesure la présence du fichier, pas celle du correctif.

## Point 6 — Dépôt allégé ✅

`Snake'on/SkinsTest/` pesait **13,6 Mo sur 21,1** versionnés, soit 64 % d'un dépôt public
servi par Pages. Aucune de ces 28 images n'est chargée par le jeu : une seule est citée,

**doublon exact** de celui d'`ia-assets` (md5 identiques).

Retirées du suivi, pas du disque. Témoin joué sur l'ignore :

```bash
git check-ignore -v "Snake'on/SkinsTest/DragonIce.png"
# .gitignore:14:Snake'on/SkinsTest/	Snake'on/SkinsTest/DragonIce.png
```

Résultat mesuré : **105 → 77 fichiers suivis, 21,1 → 7,5 Mo**.

**Réserve dite avant l'arbitrage, et qui reste vraie** : le `.git` pèse 19 Mo (pack 17,4 Mo)
et ne bouge pas. Un `git clone` reste aussi lourd qu'avant — seuls le checkout et ce que
Pages sert s'allègent. Alléger l'historique demanderait de le réécrire, ce qui n'a pas été
fait et n'est pas recommandé.
